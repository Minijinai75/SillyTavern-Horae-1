Horae 設定檔
匯出可分享的行為開關、僅限主角選項、自動摘要行為、自訂提示詞與 RPG 設定。本機 API 憑證、向量連線／索引設定及回覆後 API 路由開關會留在此裝置，不會匯出。
將設定儲存到角色卡
將目前的 Horae 設定儲存到角色卡（不含 API 憑證）。切換到這張卡時，會依下方選擇的方式自動套用，讓西幻／現代／武俠等不同主題的卡片各自保留 RPG 與提示詞設定。
以彈出視窗詢問最安全（預設）；自動套用適合你信任的角色卡作者；僅顯示提示會在抽屜上方顯示橫幅，不主動打擾；不處理則會完全跳過自動偵測。
基本設定
擴充功能的介面顯示語言。「自動偵測」會依瀏覽器／酒館設定自動選擇。
控制 AI 在 horae 標籤中使用的語言（事件描述、NPC 描述等）。格式標記會維持不變，只影響描述文字。
影響 AI 智慧補全、單則分析、手動／自動摘要等 Horae 背景 AI 任務。預設不使用酒館主要預設；只有在破不開甲或背景任務輸出異常時才開啟。
關閉後，上方圖示會完全隱藏且不保留空位。可透過擴充面板（積木圖示）中的「Horae 時光記憶」欄位重新開啟。
訊息面板佔聊天區域的寬度百分比（50～100）。寬螢幕美化可調低以避免溢出；向右位移可微調面板的水平位置。

進階設定
控制傳送給 AI 的一般層級劇情軌跡數量。0 = 不傳送一般事件；重要／關鍵／摘要仍會傳送。

原版合併注入 會將劇情軌跡與狀態資訊放在同一個注入區塊。
獨立前置注入 會將劇情軌跡另外放在聊天紀錄中較前面的位置。

自訂日曆
為非西曆世界觀（四季月、奇幻曆法等）定義月份名稱與天數。啟用後會依這套日曆推算劇情中的相對時間；西曆世界觀請勿開啟。
傳送給 AI 的內容
控制哪些資訊會隨提示詞傳送給 AI。關閉可節省 Token，但 AI 將無法「記住」這些內容。
目前注入 Token：計算中...
歷史事件摘要與相對時間計算。關閉後，AI 將無法知道「幾天前」發生了什麼。
在場角色、服裝描述、好感度與角色資訊。關閉後，AI 可能會寫錯服裝。
關閉後不再注入任何角色的好感度數值；不影響其他角色資訊。
關閉後，不再注入主要角色（卡片本體 + 置頂 NPC）的性格簡述；不影響其他 NPC。
目前持有的物品及所在位置。關閉後，AI 可能會「憑空」取出不存在的物品。
紀錄地點的固定物理特徵，讓不同回合的場景描寫保持一致。開啟後，AI 會在第一次到達新地點時紀錄特徵描述。
追蹤角色之間的關係變化（朋友、戀人、敵對等），AI 只在關係變化時輸出。關閉後不產生 rel: 標籤，也不注入關係網路提示詞。
追蹤在場角色的情緒／心理狀態變化，協助 AI 維持角色情緒的一致性。AI 只在情緒明顯變化時輸出。
啟用後，AI 會在 <horaerpg> 標籤中輸出角色屬性條（HP／MP／SP）與技能變化。關閉時不注入提示詞，也不消耗 Token。
適用於「USER 自己描寫行為／動作，AI 不再轉述 USER 部分」的寫法。開啟後，AI 回覆時會將上一則 USER 訊息的內容也納入本則標籤結算，確保不遺漏 USER 的行為。
啟用後，下方面板會出現「標記為番外」按鈕。標記後的訊息不會被 Horae 追蹤，也不會納入自動摘要，適合在主線中穿插 if／番外／小劇場，但不會自動隱藏。
自動摘要與隱藏
尚未摘要的內容達到觸發門檻時，會自動交由 AI 將舊事件壓縮成摘要，以節省 Token。
壓縮後可在時間線中切換回原始事件查看。
最近 N 則 AI 訊息絕對不會被摘要；中間的使用者訊息會隨全文一起傳送。
全文 + 時間線事件保留的細節較完整，但會消耗更多 Token，也更容易被截斷；僅時間線事件較省 Token。
觸發條件：尚未摘要的內容達到目前門檻後自動壓縮
範例：若保留數量設為 5、摘要數量設為 12，當 AI 訊息累積到 17 則時，系統會將前 12 則整理成一則摘要。
酒館對話中通常還會穿插 user 訊息；以樓層計算時，大約會在第 34 樓摘要前 24 樓。
若改用 Token 模式，則依 Token 門檻觸發。
同一層的摘要達到此數量後，會合併成更高一層的摘要；二次摘要累積到指定數量後會繼續進行三次摘要，以此類推。
等待二次摘要的內容總字數低於此值時會跳過本輪，避免反覆壓縮造成品質下降。設為 0 即可關閉限制。
每次自動摘要最多處理幾則訊息。舊對話第一次啟用時，會分成多輪逐步處理。
每次摘要送入的文字 Token 上限，超過時會截斷至此值。
可參考各模型的上下文視窗（建議設為 30%～50%）：
Claude ≈ 80K~200K · GPT-4o ≈ 80K~128K · Gemini ≈ 100K~1000K · DeepSeek ≈ 64K
向量記憶（Beta）
對 Horae 標籤資料進行向量檢索，自動召回相關歷史片段並注入給 AI。
本機模式：將約 25 MB 的量化模型下載到瀏覽器快取，約佔用 50～80 MB 記憶體。⚠ 不建議在記憶體低於 2 GB 的手機或雲端酒館上使用；啟用前請務必確認已設定 —max-old-space-size，以解除 Node.js 的執行記憶體限制。
API 模式：使用遠端 Embedding API，不需要本機資源。支援 OpenAI Embeddings 與 Gemini v1beta/batchEmbedContents；使用 Gemini 時，請填入 Google Generative Language API 的官方基礎位址。
q4 適合大多數裝置；q8 精度較高，但檔案大小會加倍。
只能填寫 Embedding（嵌入／向量）模型！
請勿填入 LLM 聊天模型（例如 gemini 3、gpt-4 等），否則會發生錯誤。
建議：qwen3-embedding-8B（Qwen）
採 OpenAI 相容格式，會自動接上 /embeddings 路徑。
例如填入：https://dashscope.aliyuncs.com/compatible-mode/v1
填好位址與金鑰後，點選 取得模型清單。
建議：qwen3-embedding-8B
選擇預設後會立即套用目前的召回參數。小模型建議適合本機模型與免費 Embedding；大模型建議適合高維 API Embedding；搭配 Rerank 建議會先取較多候選項目，再交由 Rerank 排序。
基礎向量召回
適用於高維度 API 模型（例如 Qwen3-Embedding、text-embedding-3-large 等）。
開啟後會關閉關鍵字擴充、事件詞組比對、高頻詞懲罰等輔助啟發式功能，
完全依靠模型本身的語意理解能力進行召回，減少低品質雜訊。
如果你使用小型或低維度模型，請勿開啟，否則召回品質會下降。
開啟後會在主控台輸出門檻、頻率、去重、Rerank 等召回明細。只在疑難排解時開啟，平常使用時請關閉。
每次傳送訊息時，從向量資料庫召回最相關的 K 筆記憶並注入上下文。
相似度低於此值的記憶不會被召回。提高此值可減少雜訊。
排名前 N 且達到全文門檻的召回結果會傳送原始正文，而非摘要。設為 0 即可關閉此功能。
只有相似度達到此值的高可信度結果才會傳送全文，避免不相關內容浪費 Token。
請以逗號分隔標籤名稱。以下情況會整段移除這些標籤包住的內容：
· 向量檢索全文回顧 & Rerank 全文排序
· 時間線解析：防止小劇場中的 horae 標籤污染正文時間線
· AI 智慧補全：傳送訊息給 AI 分析前先排除
例如填入 snow, theater，便會排除 <snow>...</snow> 與 <theater>...</theater>。
HTML 註解 <!-- ... --> 預設已排除，不需要填寫。
Rerank 二次排序
完成向量召回後，再使用 Rerank 模型替候選結果重新排序，可明顯提高召回準確度，
將真正相關的內容排到前面、較不相關的內容往後移，讓 AI 收到更準確的記憶。
需要另外設定 Rerank 模型的 API（與 Embedding 模型不同），
建議模型：Qwen3-Reranker、bge-reranker-v2-m3、bce-reranker
填好位址與金鑰後，點選 取得模型清單。
建議：qwen3-Reranker-4B / 8B
Rerank 預設會使用摘要排序。開啟後會改用原始訊息全文排序，
可以捕捉摘要遺漏的細節，但對模型的上下文長度要求很高。
僅適用於長上下文 Rerank 模型（例如支援 32K 的 Qwen3-Reranker 系列）。
bge-reranker-v2-m3（≤1024 有效）與 bce-reranker（≤512）等短上下文模型
請勿開啟，否則全文會被截斷，效果反而更差。
開啟 Rerank 時，會先以較寬鬆的門檻召回指定數量的候選項目，再交給 Rerank 排序。建議設為 20～40。
開啟 Rerank 時使用的 embedding 召回門檻，會遠低於上方的「最低相似度門檻」，讓真正相關但 embedding 分數較低的樓層也有機會進入 Rerank 排序。
低於此分數的 Rerank 結果會被捨棄。不同模型的分數尺度差異很大：嚴格 ≈ 0.85、平衡 ≈ 0.5、寬鬆 ≈ 0.2，請依使用的模型調整。
