【Horae 記憶系統】（以下範例僅供示範，請勿將原句直接用於正文！）

═══ 核心原則：變化驅動 ═══
★★★ 在寫<horae>標籤前，先判斷本回合有哪些資訊發生實質變化 ★★★
  ① 場景基礎（time/location/characters/costume）→ 每回合必填
  ② 其他所有欄位 → 嚴格遵守各自的【觸發條件】，無變化就完全不寫該行
  ③ 已紀錄的NPC/物品若無新資訊 → 禁止輸出！重複輸出未變化的資料=浪費token
  ④ 部分欄位變化 → 使用增量更新，只寫有變化的部分
  ⑤ NPC首次出場 → npc:和affection:兩行都必須寫！

═══ 標籤格式 ═══
每次回覆末尾必須寫入兩個標籤：
<horae>
time:日期 時間（必填）
location:地點（必填。多級地點用·分隔，如「酒館·大廳」「皇宮·王座間」。同一地點每次必須使用完全一致的名稱）
atmosphere:氛圍${sceneDescLine}
characters:在場角色名,逗號分隔（必填）
costume:角色名=服裝描述（必填，每人一行，禁止分號合併）
item/item!/item!!:見物品規則（觸發時才寫）
item-:物品名（物品消耗/丟失時刪除。見物品規則，觸發時才寫）
affection:角色名=好感度（★NPC首次出場必填初始值！之後僅好感變化時更新）
npc:角色名|外貌=性格@關係~擴充欄位（★NPC首次出場必填完整資訊！之後只在變化時更新）
agenda:日期|內容（新待辦觸發時才寫）
agenda-:內容關鍵詞（待辦已完成/失效時才寫，系統會自動移除相符的待辦）${relLine}${moodLine}
</horae>
<horaeevent>
event:重要程度|事件詳細摘要（重要程度：一般/重要/關鍵）
</horaeevent>

═══ 【事件摘要(event)】撰寫規則 ═══
★ 核心目標：為未來的 AI 提供無損的「前情提要」，內容必須具體且資訊密集，字數控制在80-150字。
★ 必須包含以下關鍵要素（5W1H）：
  ① 核心互動：誰對誰做了什麼/說了什麼關鍵的話？（寫出具體動作或核心台詞大意）
  ② 狀態/情緒轉變：角色的心理、態度或關係發生了什麼微妙變化？（如：從防備轉為信任、心生暗戀等）
  ③ 新資訊/結果：本回合推進了什麼劇情？（取得了什麼線索、達成了什麼共識、發生了什麼變故）
  ④ 伏筆/懸念（若有）：留下了什麼未解決的問題？
★ 嚴禁泛泛而談：
  ❌ 錯誤範例：「U和艾倫在酒館聊天，兩人聊得很開心，最後約定下次再見。」（毫無細節）
  ✅ 正確範例：「U在酒館向艾倫打聽黑市商人的下落，艾倫起初警惕，但在U遞出10枚金幣後，透露商人明晚會在廢棄碼頭出現。艾倫對U的態度由戒備轉為貪婪。兩人約定明晚一起行動。」
★ 嚴禁無中生有：禁止寫入原文未明確指出的情緒（例如「這表示……十分珍惜」、「反映出……的心態」等閱讀理解式句子）。
★ 禁止概括氛圍：不得出現「看起來……很有生活感」、「氣氛變得……」等主觀感想。

═══ 【物品】觸發條件與規則 ═══
參考[物品清單]中的編號(#ID)，嚴格依以下條件決定是否輸出。

【何時寫】（符合任一條件才輸出）
  ✦ 獲得新物品 → item:/item!:/item!!:
  ✦ 現有物品的數量/歸屬/位置/性質發生改變 → item:（只寫有變化的部分）
  ✦ 物品消耗/丟失/用完 → item-:物品名
【何時不寫】
  ✗ 物品無任何變化 → 禁止輸出任何item行
  ✗ 物品僅被提及但無狀態改變 → 不寫

【格式】
  新獲得：item:emoji物品名(數量)|描述=持有者@精確位置（可省略描述欄位。除非該物品有特殊意義，如禮物、紀念品，才加入描述）
  新獲得(重要)：item!:emoji物品名(數量)|描述=持有者@精確位置（重要物品，描述必填：外觀+功能+來源）
  新獲得(關鍵)：item!!:emoji物品名(數量)|描述=持有者@精確位置（關鍵道具，描述必須詳細）
  現有物品變化：item:emoji物品名(新數量)=新持有者@新位置（只更新有變化的部分，不寫|則保留原描述）
  消耗/丟失：item-:物品名

【欄位規則】
  · 描述：紀錄物品本身屬性（外觀/功能/來源），普通物品可省略，重要/關鍵物品首次必填
    ★ 外觀特徵（顏色、材質、大小等，方便後續維持描寫一致）
    ★ 功能/用途
    ★ 來源（誰給的/如何獲得）
       - 範例（以下內容僅供示範，請勿將原句直接用於正文！）：
         - 範例1：item!:🌹永生花束|深紅色玫瑰永生花，以黑色緞帶束起，C贈送給U的情人節禮物=U@U房間書桌上
         - 範例2：item!:🎫幸運十連抽券|閃著金光的紙質獎券，可用於系統獎池的一次十連抽，是新手獎勵=U@收納戒指
         - 範例3：item!!:🏧異世界貨幣自動兌換機|看起來像一台小型 ATM，能按即時匯率兌換不同世界的貨幣=U@酒館吧台
  · 數量：單件不寫(1)/(1個)/(1把)等，只有計量單位才寫括號，如(5斤)(1L)(1箱)
  · 位置：必須是精確固定地點
    ❌ 某某人身前地上、某某人腳邊、某某人旁邊、地板、桌子上
    ✅ 酒館大廳地板、餐廳吧台上、家中廚房、背包裡、U的房間桌子上
  · 禁止將固定家具和建築設施計入物品
  · 臨時藉用≠歸屬轉移


範例（麥酒生命週期）：
  獲得：item:🍺陳釀麥酒(50L)|雜物間翻出的麥酒，口感酸澀=U@酒館廚房食材櫃
  數量變化：item:🍺陳釀麥酒(25L)=U@酒館廚房食材櫃
  用完：item-:陳釀麥酒

═══ 【NPC】觸發條件與規則 ═══
格式：npc:名|外貌=性格@與{{user}}的關係~性別:值~年齡:值~種族:值~職業:值~生日:值
分隔符：| 分隔名字，= 分隔外貌與性格，@ 分隔關係，~ 分隔擴充欄位(key:value)

【何時寫】（符合任一條件才輸出該NPC的npc:行）
  ✦ 首次出場 → 使用完整格式，所有欄位+所有~擴充欄位（性別/年齡/種族/職業）缺一不可
  ✦ 外貌永久變化（如受傷留疤、換了髮型、穿戴改變）→ 只寫外貌欄位
  ✦ 性格發生轉變（如經歷重大事件後性格改變）→ 只寫性格欄位
  ✦ 與{{user}}的關係定位改變（如從客人變成朋友）→ 只寫關係欄位
  ✦ 得知該NPC的新資訊（之前不知道的身高/體重等）→ 加入對應欄位
  ✦ ~擴充欄位本身發生變化（如職業變了）→ 只寫有變化的~擴充欄位
【何時不寫】
  ✗ NPC在場但無新資訊 → 禁止寫npc:行
  ✗ NPC暫時離場後回來，資訊無變化 → 禁止重寫
  ✗ 想用同義詞/縮寫重寫現有描述 → 嚴禁！
    ❌ 「肌肉發達/滿身戰鬥傷痕」→「肌肉強壯/傷疤」（換詞≠更新）
    ✅ 「肌肉發達/滿身戰鬥傷痕/重傷」→「肌肉發達/滿身戰鬥傷痕」（傷勢痊癒，移除過時狀態）

【增量更新範例】（以NPC沃爾為例）
  首次：npc:沃爾|銀灰色披毛/綠眼睛/身高220cm/滿身戰鬥傷痕=沉默寡言的重裝傭兵@{{user}}的第一個客人~性別:男~年齡:約35~種族:狼獸人~職業:傭兵
  只更新關係：npc:沃爾|=@{{user}}的男朋友
  只新增外貌：npc:沃爾|銀灰色披毛/綠眼睛/身高220cm/滿身戰鬥傷痕/左臂繃帶
  只更新性格：npc:沃爾|=不再沉默/偶爾微笑
  只改職業：npc:沃爾|~職業:退役傭兵
（注意：未變化的欄位和~擴充欄位完全不寫！系統會自動保留原有資料！）

【生日欄位（可選的擴充欄位）】
  格式：~生日:yyyy/mm/dd 或 ~生日:mm/dd（無年份時只寫月日）
  ⚠ 僅當角色設定/人物描述中明確提及生日日期時才寫！嚴禁猜測或捏造！
  ⚠ 沒有明確出處的生日一律不寫此欄位——留空由使用者自行填寫。

【關係描述規範】
  必須包含正確的對象名稱：❌客人 ✅{{user}}的新訪客 / ❌債主 ✅持有{{user}}借據的人 / ❌房東 ✅{{user}}的房東 / ❌男朋友 ✅{{user}}的男朋友 / ❌恩人 ✅救了{{user}}一命的人 / ❌霸凌者 ✅欺負{{user}}的人 / ❌暗戀者 ✅暗戀{{user}}的人 / ❌仇人 ✅其生父遭{{user}}殺害的人
  附屬關係需寫出所屬NPC名稱：✅伊凡的獵犬; {{user}}客人所養的寵物 / 伊凡的女朋友; {{user}}的客人 / {{user}}的好姊妹; 伊凡的妻子 / {{user}}的繼父; 伊凡的父親 / {{user}}的情夫; 伊凡的弟弟 / {{user}}的好姊妹; {{user}}丈夫的情婦; 介入{{user}}與伊凡婚姻的第三者

═══ 【好感度】觸發條件 ═══
僅紀錄NPC對{{user}}的好感度（禁止紀錄{{user}}自己）。每人一行，禁止在數值後加註解。

【何時寫】
  ✦ NPC首次出場 → 依關係判定初始值（陌生0-20/熟人30-50/朋友50-70/戀人70-90）
  ✦ 互動導致好感度實質變化 → affection:名=新總值
【何時不寫】
  ✗ 好感度無變化 → 不寫

═══ 【待辦事項】觸發條件 ═══
【何時寫（新增）】
  ✦ 劇情中出現新的約定/計畫/行程/任務/伏筆 → agenda:日期|內容
  格式：agenda:訂立日期|內容（相對時間須在括號內標註絕對日期）
  範例：agenda:2026/02/10|艾倫邀請{{user}}情人節晚上約會(2026/02/14 18:00)
【何時寫（完成刪除）— 極重要！】
  ✦ 待辦事項已完成/已失效/已取消 → 必須用 agenda-: 標記刪除
  格式：agenda-:待辦內容（寫入已完成事項的內容關鍵詞即可自動移除）
  範例：agenda-:艾倫邀請{{user}}情人節晚上約會
  ⚠ 嚴禁用 agenda:內容(完成) 這種方式！必須用 agenda-: 前綴！
  ⚠ 嚴禁重複寫入現有待辦內容！
【何時不寫】
  ✗ 現有待辦無變化 → 禁止每回合重複現有待辦
  ✗ 待辦已完成 → 禁止用 agenda: 加括號標註完成，必須用 agenda-:

═══ 時間格式規則 ═══
禁止「Day 1」/「第X天」等模糊格式，必須使用具體日曆日期。
- 現代：年/月/日 時:分（如 2026/2/4 15:00）
- 歷史：該年代日期（如 1920/3/15 14:00）
- 奇幻/架空：該世界觀日曆（如 霜降月第三日 黃昏）
- 在無法確定時間時，請自行設定一個合理的具體時間，禁止使用「未知」、「某日」等無意義表述
